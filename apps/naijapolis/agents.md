# agents.md

This document provides an overview of the PoliForge OS project architecture for developers and AI agents working on this codebase.

## Project Overview

PoliForge OS is a modular, open-source political campaign management platform built for Nigerian electoral conditions. It is a TanStack Start SSR application deployed on Netlify, using Netlify Blobs for data persistence.

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | TanStack Start (React 19) |
| Routing | TanStack Router v1 (file-based) |
| Build | Vite 7 |
| Styling | Tailwind CSS 4 |
| Storage | Netlify Blobs (`@netlify/blobs`) |
| Language | TypeScript 5.7 strict |
| Deployment | Netlify |

## Core Architecture Decision: Activity Stream

**Everything writes to `activity_stream`** (stored as `activities` in Blobs). Every domain action — donation, canvass, RSVP, volunteer signup, advocacy message, pledge — produces an activity record. This powers the real-time feed on the home page and enables cross-module analytics.

## Data Layer

Netlify Blobs (`@netlify/blobs`) is used as the persistence layer. Data is stored as JSON arrays keyed by resource type:

| Key | Type |
|---|---|
| `people` | `Person[]` |
| `activities` | `Activity[]` |
| `transactions` | `Transaction[]` |
| `pledges` | `Pledge[]` |
| `fundraisers` | `Fundraiser[]` |
| `events` | `Event[]` |
| `event_rsvps` | `EventRsvp[]` |
| `goals` | `Goal[]` |
| `canvass` | `CanvassRecord[]` |
| `advocacy` | `AdvocacyContact[]` |
| `settings` | `AppSettings` |
| `seeded` | `"true"` (flag) |

The store name is `poliforge`. On first run, `ensureSeeded()` in `db.server.ts` inserts realistic Nigerian demo data automatically.

**Important:** `db.server.ts` is SERVER ONLY. Never import it in client-side or shared code. Import shared static data from `src/lib/data.ts` instead.

## Server Functions Pattern

Each module has a `*.functions.ts` file in `src/server/` using `createServerFn` from `@tanstack/react-start`:

```ts
export const fetchPeople = createServerFn({ method: 'GET' }).handler(async () => {
  return getPeople()
})
```

Loaders call server functions:
```ts
export const Route = createFileRoute('/people')({
  loader: async () => fetchPeople(),
  component: PeoplePage,
})
```

## Naming Conventions

- **Components**: PascalCase
- **Utilities/hooks**: camelCase
- **Routes**: kebab-case files
- **Server-only helpers**: `*.server.ts` suffix (never import in client code)
- **Importable server functions**: `*.functions.ts` suffix (safe to import anywhere)

## Styling Conventions

- Tailwind CSS utility classes throughout
- `cn()` helper from `src/lib/utils.ts` for conditional class merging
- Color scheme: `green-600/700` for primary actions (Nigerian green), `gray-900` for sidebar
- No Radix UI — all UI components are built with plain Tailwind

## TypeScript Notes

- `routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin at build time. It does not exist in the source tree.
- `tsc --noEmit` will show false positives for route-related types until `routeTree.gen.ts` exists.
- Run `npm run build` or `netlify dev` to generate it.

## Key Modules

### Activity Feed (index.tsx)
The main dashboard. Displays all activities from the unified stream with filtering by type. Includes "New Donation" quick-action button. Stats cards show real-time totals from activity data.

### Finance (finance.tsx)
Three-tab view: Transactions, Pledges, Fundraisers. Fundraiser cards show progress bars computed from transaction totals. Paystack/Flutterwave/Bank Transfer/Cash channels supported.

### Canvassing (canvassing.tsx)
Door-knock logging with support level (strong/lean/neutral/opposed). Shows pending sync status for offline/USSD submissions. Linked to INEC polling unit registry.

### Polling Units
Six pre-loaded example polling units in `src/lib/data.ts` covering Lagos, Abuja, Kano, Oyo, and Rivers. In production, import the full INEC polling unit dataset and seed it at startup.

## USSD Fallback Strategy

Activities recorded via USSD get `sync_status: "pending"` and `source: "ussd"`. The canvassing and activity feed views surface these with a visual warning, enabling supervisors to verify and confirm field data.
